# 课程答疑 RAG（演示 Demo）

> **定位声明**：这是一个**独立编写的演示项目**，用于展示 RAG 的检索—生成思路与 FastAPI 工程能力。
> 它与简历中提到的实际交付项目相互独立，不代表真实系统的源码。

## 这是什么

一个最小可运行的 RAG 问答服务：知识库检索 + 大模型生成，两个环节解耦、可独立测试。

- 检索：纯 Python 实现的分词 + TF 加权 + 余弦相似度，**零外部依赖**；换真实 embedding / 向量库时只改 `score` 函数。
- 生成：可插拔的 `LLM` 接口，默认用 `FakeLLM`（确定性输出，方便测试），接真实大模型实现同接口即可。
- 内置「数据结构 / 数据库」示例知识库，打开页面就能问。

## 快速运行

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
# 打开 http://127.0.0.1:8000
```

跑测试：`pytest -q`

## 设计要点（面试可讲）

1. **检索与生成解耦**：检索只负责找出相关片段，生成只负责基于片段组织答案，两边可独立测试、独立替换。
2. **召回阈值**：相似度低于阈值视为「未命中」，避免把无关片段塞给大模型、制造幻觉。
3. **prompt 约束**：显式要求模型「只依据资料回答，资料没有就说未提及」，这是 RAG 防幻觉的关键。
4. **来源可追溯**：答案带引用片段编号，方便核对。

## 能力边界（诚实）

- 检索是**词袋余弦相似度**，不是真实语义向量（embedding）；接 Milvus / embedding 模型后检索质量会明显提升。
- `FakeLLM` 不是真大模型，返回的是拼接文本；接入真实 API 需补充鉴权与流式。
- 未做文档上传、分块持久化；知识库目前是内存硬编码。
